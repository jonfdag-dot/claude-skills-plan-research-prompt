# Generic editing examples

These examples were adapted for the starter and contain no source-project history. They illustrate reasoning rather than runtime proof.

## 14 Explicit removal without a replacement workflow

If the user directly requests removing a generic planning mandate, remove that mandate within the named scope. Inspect an actual co-loaded counterpart or generator before declaring it gone; do not introduce an equivalent replacement checklist. Preserve separate operational approvals and unrelated requirements.

## 15 Generated instruction content

If an automatically generated tool block returns after manual deletion, identify the writer and its inputs. A checked-in edit to generated output cannot establish persistence. Propose or perform the authorized source-owned change, then run the relevant deterministic generation check while preserving unrelated generated content.

## 16 A failed diagnostic tool

A linter exception means that tool's coverage is unknown, not that the instruction passed or violated policy. Record the exact error and continue independent supported changes. Do not fix the diagnostic tool unless that repair is within the user's request.
