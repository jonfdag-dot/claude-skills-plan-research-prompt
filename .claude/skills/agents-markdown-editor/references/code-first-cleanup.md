# Code and context anchors for instruction cleanup

Select this reference when a loaded root instruction file exceeds its agreed byte ceiling, its inventory has drifted or a generated tool block keeps returning. Use the editor's loaded-set and placement checks first. Ordinary cleanup remains STATIC under the [canonical verification policy](../../skill-creator/references/verification-and-eval-admission.md).

## Historical basis and limits

The earlier text also required transcript counting, delegated every product eval, removed zero-use tools after two weeks and regenerated Codex instructions by script. Those are separate operational choices, not ordinary cleanup gates. Missing or incomplete usage observations do not prove disuse. Do not infer model effectiveness, context cost or savings from historical counts or a smaller file.

## Establish the requested shape

Agree or recover the task's byte ceiling and context that must remain. Measure the actual loaded set and section sizes, then distinguish verified defects from discretionary cuts. A target size does not authorize dropping required environment knowledge.

Preserve non-obvious architecture seams, required commands, unusual runtime behavior and the routing needed to reach detailed owners. Convert inventories to authoritative pointers where appropriate, while keeping facts a simple tree listing cannot show. Search for required policy in broader loaded scopes before declaring a line redundant.

## Verify anchors before proposing cuts

Check each cited file, symbol, inventory, count, deadline and range against the actual source. A missing pointer or contradicted fact is a verified finding; an unexplained style preference is not. Code anchors explain what exists, tests identify proof and documentation records rationale.

Prefer stable symbol and file identities to fragile line numbers in maintained instructions. Use an existing project freshness checker when the requested cleanup depends on it. A reported stale document differs from a missing source or undeclared symbol; follow the check's actual contract.

Copied code or incident narratives may be moved or trimmed only within the authorized scope. Preserve their reusable policy or rationale and any canonical ownership. Do not discard material solely because its age or length suggests it might be stale.

## Generated blocks and enforcement

Identify the generator, owned markers, version, affected files and actual available controls. Inspect the postflight rather than assuming that a flag removes an injected block. A future generator run may restore a cut, so a instruction-file edit alone cannot guarantee persistence.

An existing wrapper or deterministic check can establish the required postcondition. Writing a wrapper, changing a hook, uninstalling a tool or editing MCP/settings is separate implementation and authority; the editor records needed changes to locked surfaces instead of making them. Preview a tool's affected scope before recommending uninstall or removal.

Use the native runtime's loaded instruction placement. Claude rules and Codex instruction files have different loading mechanics; a separately authorized native port must reconcile portable policy while preserving runtime differences. Do not mandate a project-specific regeneration script or an unconditional hand-copy strategy.

## Optional observations and experiments

Read supplied observations only when they answer a named question and access is authorized. Transcript mining, telemetry collection, hooks for observation, scheduled remeasurement and model trials do not follow from size cleanup.

If usage informs a discretionary proposal, record its source, window, completeness and unavailable data. Inspect capability, callers and required routing before proposing retirement; absence of recorded calls alone is insufficient. A behavioral effectiveness question requires canonical admission and a finite run allowance.

## Bounded order of work

1. Audit the loaded set; record runtime/version, model if available and artifact hashes.
2. Recover the requested byte ceiling and required context; measure relevant sections.
3. Verify inventories and pointers against the tree and selected source owners.
4. Prepare the editor's numbered sheet for discretionary items, or apply the direct bounded request under its existing authorization.
5. Run applicable deterministic checks, confirm required context and native parity, and review the owned diff.
6. Report actual results, remaining locked-path changes and material uncertainty, then stop.

Select plan or research-library validation only when this operation actually writes those artifacts. Do not schedule a new measurement, start an eval or broaden checks merely because the cleanup is complete.
