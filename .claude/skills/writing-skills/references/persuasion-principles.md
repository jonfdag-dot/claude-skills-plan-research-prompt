# Historical persuasion hypotheses for skill design

Select this reference only when an admitted wording experiment concerns these hypotheses. It preserves a historical taxonomy, not a general authoring prescription. The [canonical verification policy](../../skill-creator/references/verification-and-eval-admission.md) governs any model execution.

## Evidence boundary

Cialdini's *Influence: The Psychology of Persuasion* (2021, Harper Business) describes human influence. Human psychology does not establish that the same technique improves engineering skill compliance in an LLM. Research on persuasive objectionable requests also uses a different outcome and workload; it does not supply acceptance evidence for authorized engineering work. No source-installation evidence register is included; verify the original evidence before relying on transfer to an LLM workload.

The earlier local reference asserted that LLMs respond like humans, emphatic language removes decision fatigue and clear triggers cause automatic execution. Those causal claims are unverified for the current local models and tasks. Missing evidence also does not establish that the techniques never help. Treat them as hypotheses to test only when an admitted question requires it.

## Seven historical categories

| Category | Human influence concept | Candidate wording feature | Transfer limit or risk |
|---|---|---|---|
| Authority | Deference to expertise or credentials | Name the real policy owner and required action | Capital letters, invented authority and absolute language do not enforce permissions |
| Commitment | Consistency with prior statements | State the intended action and record required steps | Announcing an action does not prove it occurred |
| Scarcity | Urgency or limited availability | State a real deadline or dependency | False urgency can push work past its authorized scope |
| Social proof | Conformity to others' behavior | Cite relevant observed practice with its scope | “Everyone does this” is not evidence or a universal requirement |
| Unity | Shared identity or goals | Describe the user's requested outcome plainly | A persona does not replace native role, tools or sandbox |
| Reciprocity | Obligation to return benefits | No ordinary engineering requirement follows | Favor or guilt framing supplies no task authority |
| Liking | Preference for cooperation with people one likes | Maintain respectful communication | Agreement or praise is not correctness evidence |

The historical combinations were authority/commitment/social proof for discipline, moderate authority/unity for technique guidance, unity/commitment for collaboration, and clarity for references. These are candidate experiment arms, not a required style table. Do not load a roster of techniques or force emphasis into every skill.

## Safe wording examples

A statement can communicate a policy without destructive teaching procedures:

```markdown
If required verification is missing, preserve existing work, identify the unresolved requirement and run the smallest authorized check before reporting completion.
```

A real dependency can be stated conditionally:

```markdown
When this operation changes routing metadata, rebuild the affected registration before running its focused deterministic probe.
```

These examples express observable conditions. They make no claim that a psychological principle guarantees compliance. Do not prescribe deleting working code, starting over, bypassing permissions or pretending an experiment is a real emergency.

## Using the hypotheses

Identify the behavior, workload and possible failure first. Use current valid evidence when available. If an admitted comparison needs a wording arm, change only the relevant feature, preserve task authority and correctness criteria, and report the model, artifact identities, cases, grader and actual results. An evaluator's explanation of why wording influenced it is a suggestion, not causal proof.

Retain genuine qualifications and permitted exceptions. Prefer a clear condition to an invented universal rule. The user's goal and the applicable permission boundary remain binding regardless of rhetorical style.
